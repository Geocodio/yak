## What Yak does

<CardGrid>
  <Card title="Takes work where you are" icon="rocket">
    Slack mentions, Linear issues, Sentry alerts, forwarded email, GitHub
    comments, or a thread you start in the dashboard. Each channel is
    optional.
  </Card>
  <Card title="Works in threads" icon="comment">
    Each piece of work is a thread with its own sandbox. Send a message while
    Claude works and it steers the running turn. Split work into sub-threads,
    or work across several repositories at once.
  </Card>
  <Card title="Opens pull requests" icon="approve-check">
    One pull request per changed repository, with screenshots and video
    walkthroughs for UI changes. A human reviews every pull request. Yak has
    no merge authority.
  </Card>
  <Card title="Moves to your computer and back" icon="laptop">
    Teleport a Claude Code session to Yak and back with the `yak` command,
    open a shell in the sandbox, or watch a live preview of the work.
  </Card>
</CardGrid>

## Design philosophy

- **A thread, not a one-off run.** Yak does the first pass, and you keep going in the same thread until the work is right.
- **Meet people where they are.** Slack in, Slack out. Linear in, Linear out. The dashboard is there when you want to watch or steer.
- **Clarify, do not guess.** Ambiguous requests get multiple-choice options grounded in the actual code.
- **A human reviews every change.** The output is always a pull request. Yak has no merge authority.
- **Your accounts, your limits.** Each thread runs on one Claude account that you choose.
